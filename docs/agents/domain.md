# Domain documentation

This project has one domain context.

Before designing, implementing, or reviewing:
1. Read [the glossary](../../GLOSSARY.md).
2. Read the [ADRs](../adr/) relevant to the change.
3. Read the applicable spec or ticket.

Use glossary terms consistently in code, tests, tickets, and discussion.
Keep glossary definitions about the domain, not implementation details.

Surface conflicts with existing ADRs before proceeding. Agree on a
revised decision rather than silently overriding one.
