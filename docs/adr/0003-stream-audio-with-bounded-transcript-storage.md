# Stream audio internally without a recording-duration cutoff

Transcribe bounded audio windows while recording continues, retain committed text internally, and publish the complete transcript only after the user stops and finalization succeeds. The user rejected a timed cutoff: fixed audio storage must be recycled rather than sized for an entire session. This adds chunk-boundary and buffer-ownership complexity and requires inference to keep pace with capture; default to a 1 MiB transcript capacity, configurable as part of the whole-program comptime storage layout, and fail visibly on text or audio-backlog exhaustion instead of silently truncating output, dropping speech, or growing storage. A toggle during finalization supersedes that session and starts a fresh recording, but background inference during recording does not change the toggle's normal stop meaning.
